## 具体问题与修复

### 安全存储

固定来源仍为 CPF `ecc4257040163da3c4dd64d4fced5d4d24676a53`，Dart 主包 `9.2.4`，
OH 实现 `1.2.2`；EasyNode 路线的 `_selectOptions()` 空 options 回退和 macOS 参数兼容保持不变。

原生实现的部分 catch 会在读失败时返回空字符串、写/删失败时回复成功，同步异常还有不回复
MethodChannel 的路径。补丁把这些失败回传为 Flutter 错误；只有键不存在才作为正常的空结果。
同一插件实例的操作串行执行，避免首次创建密钥与并发读写互相覆盖。

2026-09-16 用户构建日志补记：补丁应用后进入 ArkTS 编译，六处 `throw e` 触发
`arkts-limited-throw`，分别在 write、read、readAll、delete、deleteAll 和 decodeRawValue。
已改为带操作名称的 `throw new Error(...)`，继续经插件 handler 以 `SECURE_STORAGE_FAILED`
向 Dart 回传失败；原有错误日志保留，未恢复吞错或清空数据行为。
构建入口增加对已记录旧补丁的识别和定向升级，新缓存直接应用修正后的完整补丁。
此次仅根据日志修改代码，尚未应用或编译验证；日志中的 810 条警告不作为这六处错误的修复依据。

存储名 `FlutterSecureStorage`、数据键前缀、AES/RSA 密钥的 Preferences 名称和标识均保留。
继续按磁盘记录的算法读写，不在普通读取期间删除旧密钥或异步重加密全部凭据。
未知算法或解密错误向 Dart 报错；不走 `resetOnError` 的全量清空路线。

读取失败时登录页可提示重新输入；登录结果持久化失败会提示“无法保存登录状态”，不会冒充网络
错误或保存成功。重新输入账号密码不保证能修复损坏的原生密钥；这类错误不会触发自动删库、
清空设置或重置全部安全存储。

### 认证与账号边界

SCU 登录仅在 token、账号绑定和时间戳全部持久化后发布 ready。写入过程及明确退出时使用
`ohos_session_signed_out_v1` 标记禁止恢复未完成或已经退出的会话；成功提交新登录后移除标记。
存储操作失败会保留错误结果，仍取消内存中的旧会话和下游状态。

登录结果有请求序号和会话代次检查，SSO 有请求及会话检查。退出后晚到的登录、续期和 SSO
结果不能重新缓存会话。Provider 等待上一轮退出清理完成再开始新登录。
办事大厅、Passpoint 和报修的请求在获取认证、发送业务请求及接收响应时核对会话；
认证重试前同样检查，阻止把旧账号的表单或 MAC 操作发到新账号会话。

这些检查不能撤销服务器已经收到的提交。退出、切换账号或关闭页面后，已经发送的请求可能
完成；补丁阻止后续上传/提交以及旧结果回写，不自动再次提交非认证错误下的业务操作。

### 表单和上传

办事大厅原先逐字段把本地文件替换成已上传附件，只有最终提交失败才恢复；第二个附件上传
失败会跳过恢复。现在使用独立的提交快照，页面原值不在上传过程中改变，已有附件对象也保留。
上传与提交期间禁用表单编辑。账号切换后丢弃旧 schema、部门信息与表单，并忽略旧加载结果。

报修固定本次提交的地址、项目、描述、预约时间和图片列表，防止异步上传期间混用新旧值。
选图读取失败、上传失败和部门预取失败都有处理；忙碌状态由 finally 释放。
账号切换重置表单与项目选择器，预约日期/时段结果也检查会话。图片选择继续受三张、10 MiB
和既有扩展名限制约束，不新增压缩或格式转换依赖。

两个上传接口都拒绝空文件，保留原 multipart 字段和文件传输方式。上传不自动跟随重定向，
以便认证层识别失效；检查非 2xx 响应，并为响应体读取增加超时，避免只等到响应头后永久等待。
服务端返回明确认证失效时仍沿用原有恢复策略；普通上传错误保留给用户处理。

## 旧安装兼容依据与策略

根仓库 `v2.2.0` 的 Dart 源码可读取，其中 SCU 的 `scu_access_token`、
`scu_principal_binding_v1`、`scu_login_timestamp`、保存账号密码的键，以及 CCYL 的
`ccyl_session_v2` 与当前名称一致。该标签仅作为 Dart 对照，不能证明两个月前的 OH HAP
使用的就是这套完整源码、原生插件提交和加密算法。旧 `ohos/` 版本声明不足以补全这项证据。

| 存量记录 | 本次处理 |
| --- | --- |
| SCU token + 有效账号/指纹绑定 | 同键读取，符合现有过期规则时恢复；过期后沿用续期流程 |
| SCU token 缺失、不可读或没有可信绑定 | 不根据缓存姓名或保存的密码猜测 token 归属；保留原记录，进入重新登录流程 |
| 保存的账号密码 | 同键读取，完整且读取成功才参与自动登录；读取失败显示恢复提示，保存时最后写入“记住密码”标记 |
| CCYL | 继续遵循上游 `ccyl_session_v2` 的账号绑定和旧格式清理规则；恢复异常不再因随后的删除失败中断初始化 |
| 旧 `zhhq_token_key` | 无账号归属，OH 不直接恢复；需要报修时按当前 SCU 账号重新 SSO，不推断它属于当前用户 |
| 新 `ohos_zhhq_session_v1` | 在原安全存储中用单条 JSON 保存 `principal` 和 `tokenKey`，读取时核对账号；旧键在明确退出/会话失效时按认证清理规则处理 |
| 课表、设置、背景与余额历史 | 不因凭据兼容问题清空；遵循现有数据生命周期 |
